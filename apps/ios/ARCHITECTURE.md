# Family Gifting — iOS foundation

**Target:** `FamilyGifting`, iOS 26+, Swift 6 complete concurrency, `dev.familygifting.app`. XcodeGen owns `project.yml`; generated projects and build products are ignored. `Config/Base.xcconfig` optionally includes ignored `Local.xcconfig`; no signing identity belongs in source. One local Swift package, `FamilyGiftingKit`, owns API/domain/session/fixtures and the Confetti design system. No third-party runtime dependencies. The app owns observable presentation state and SwiftUI features.

**Flow:** SwiftUI → main-actor `AppModel` → `APIClient` actor → injected transport → `/api/v1`. `/health` validates the origin before saving it. First launch starts with a blank server address. Previously validated LAN and private HTTPS origins remain available. Only `NSAllowsLocalNetworking` is enabled, with a local-network explanation; no broad ATS exception. A wrong address, denied local-network permission, or expired session is a visible recoverable error. Refresh on foreground/pull-to-refresh; cursor “load more” on native lists. Serial requests bound load for this small family. No websocket is needed until native Kanban arrives.

**Auth:** The app currently uses the shipping LAN contract. Access tokens last 24 hours. Local expiry retains the origin-bound Keychain identity so previously signed-in users can save ideas offline and sync after signing in again. An authenticated API 401 clears the invalid bearer. The existing bearer-only `POST /auth/refresh` requires a valid access token.

The Kit implements the draft native session protocol behind the explicit `nativeSessionsFor` origin capability. The app leaves that capability unset. With a configured capability, login and registration send `client: ios`. A legacy response falls back to access-only behavior, and a registration response without a token follows with login. A paired response enables serialized rotation through `/auth/session/refresh` with an atomic Keychain update. A lost response can retry the predecessor within the server's grace window. The app uses a conservative 25-second cutoff and anchors replacement expiries to the first attempt. Device and all-session revocation are implemented in the Kit. Draft endpoints are covered with injected transports and require independent server review and deployment before any app enables the capability.

**Native now:** five tabs, People cards/search/groups, a skippable five-step creator with PhotosPicker upload, field-by-field profile completion, Gifts filters/detail/edit/status/swipes, Ideas inbox, upcoming/month/season Events, holiday selection and native event plans. Stickers use the Confetti web format in `photo_url` and render natively across Home and People. Replacing an uploaded photo requires confirmation. Older device-local sticker preferences are retired. Profile group, size and interest arrays use last-write-wins replacement under the existing API. Existing account responses have no name, so Home uses “Hello”. Home's heading and hero share `dashboard.primaryOccasion`. Optional feeds can fail independently of the everyday screens.

**Capture:** every tab has a quick capture action. The account/origin-scoped atomic journal persists before upload, refreshes on launch/foreground/network changes, and survives termination and sign-out. Sign-out clears credential and presentation state. A later sign-in to the same account can recover its journal. Older credential-fingerprint account mappings remain for offline compatibility. Each sync operation is bound to the API session revision. The `ios:capture:<uuid>` marker uses the existing `source` field to reconcile receipts. The web gift detail currently displays that field as a badge and in its link label. Moving receipt identity to a dedicated server idempotency field is future work. An ambiguous attempt can be retried explicitly after a fresh receipt search completes. The API has no atomic idempotency key, so an earlier request can still appear after a successful absence check. Discard removes only the pending local copy. Unlinked catalog ideas and list-item inbox ideas retain their separate identities.

**Future tunnel:** LAN password registration stays open only while the effective household allowlist is empty; configuring it closes native and web password sign-up. Any future public tunnel would expose account creation and the shared dataset to anyone who could reach that origin, so tunnel work requires a separate server access review.

**Web:** Budget, Lists, Assignments, and Admin use the existing ephemeral session-sharing WKWebView. Native navigation handles person/gift/event routes, and Settings includes the origin. Document-start injection sets existing web token/expiry keys only in the trusted main-frame origin. Cross-origin links leave the view without credential injection. The bridge still needs a device check against the deployed build before TestFlight.

**Design:** `Tokens/confetti.tokens.json` → `Scripts/generate-tokens.py` → `ConfettiTokens.swift`. Run `--check` in verification. JSON seeds exactly the current web palette/type/spacing/radii/shadows; future web work should generate CSS variables from this same JSON and remove duplicate literals (web untouched here). The `active-theme` response alone selects Christmas; dates never activate it locally. Bundled Montserrat Bold/Open Sans Regular retain OFL licenses. Intentionally light-only until a reviewed dark palette exists. Dynamic Type fonts, adaptive hero layout, native tab/navigation/sheets, semantic labels and ≥44pt controls; native glass stays in system chrome. Together Bow paths mirror `BrandMark.tsx`; icon/launch resources retain that geometry.

## Countdown and Share

The proposed App Group is `group.dev.familygifting.app`. The app binds it to the current server origin and user ID, writes the next occasion title and calendar date after refresh, and requests a WidgetKit timeline reload after a cache change. Sign-out, an invalidated login, server changes and account switches clear the active countdown. Expired access clears the countdown while retaining the offline outbox binding. Snapshots expire with access or after seven days, whichever comes first, and the widget hides past dates. Its Home Screen gallery preview uses a generic event.

The share extension can save an HTTP(S) link or text offline after the main app establishes an account binding. A binding revision prevents a share sheet opened before an account change from saving to the next account. Outbox items retain their original origin and account across sign-out. The app imports only matching items into its private queue before sync. It preserves item IDs across the handoff and retires each outbox item after the private journal write succeeds. Both extensions link the extension-safe package product. Bearer credentials stay in the app's Keychain.

The expected bundle IDs are `dev.familygifting.app.countdown` and `dev.familygifting.app.shareidea`. Binding the app and both extensions to the same App Group for device signing remains open under `req_01M85BY31FN9E5EN93K4MD47FX`. The local unsigned simulator review build can use a per-device synthetic store. The Release archive excludes that mode. Offline fixtures use only invented data.

## Read-only server smoke check

From `apps/ios/FamilyGiftingKit`, run `swift run fg-smoke --server <url>` with `FG_EMAIL` and `FG_PASSWORD` already exported. Credentials are read only from the environment; use a throwaway account. Output contains endpoint paths and OK, HTTP status, or decoding field path; no tokens, passwords, or response bodies. Empty collections skip dependent detail probes. The tool signs in, then performs only reads. Do not run it against a live server during mocked-only development.
