# Family Gifting — iOS foundation

**Target:** `FamilyGifting`, iOS 26+, Swift 6 complete concurrency, `dev.familygifting.app`. XcodeGen owns `project.yml`; generated projects and build products are ignored. `Config/Base.xcconfig` optionally includes ignored `Local.xcconfig`; no signing identity belongs in source. One local Swift package, `FamilyGiftingKit`, owns API/domain/session/fixtures and the Confetti design system. No third-party runtime dependencies. The app owns observable presentation state and SwiftUI features.

**Flow:** SwiftUI → main-actor `AppModel` → `APIClient` actor → injected transport → `/api/v1`. `/health` validates the origin before saving it. Default origin is the requested LAN gateway; HTTPS private origins require no code change. Only `NSAllowsLocalNetworking` is enabled, with a local-network explanation; no broad ATS exception. A wrong address, denied local-network permission, or expired session is a visible recoverable error. Refresh on foreground/pull-to-refresh; cursor “load more” on native lists. Serial requests bound load for this small family. No websocket is needed until native Kanban arrives.

**Auth:** Keychain stores bearer credential + expiry, scoped to server origin. One API actor attaches it, expires it locally, clears it on 401, and throws a typed unauthorized error which the app routes to sign-in. The checked-in API does expose `POST /auth/refresh`, contrary to the brief, but it requires an unexpired bearer. The client exposes it without auto-renewing; it cannot recover expired sessions. Register uses the same email/password/confirmation fields as web. The explicit renewal method can host a future rotating refresh implementation. **First requested server change:** add rotating, revocable 30-day refresh sessions (a revised `POST /auth/refresh`, new `POST /auth/logout`, device/session revocation); retain short-lived access tokens, return `expires_in` and a refresh credential, hash refresh tokens at rest. Today users sign in again after 24 hours.

**Native now:** five tabs, People cards/search/groups, a skippable five-step creator with PhotosPicker upload, field-by-field profile completion, Gifts filters/detail/edit/status/swipes, Ideas inbox, upcoming/month/season Events, holiday selection and native event plans. The creator's sticker/color preference stays on this device until the API exposes those fields. Existing account responses have no name; Home uses “Hello”. Home's heading and hero share `dashboard.primaryOccasion`.

**Capture:** every tab has a quick capture action. The account/origin-scoped atomic journal persists before upload, refreshes on launch/foreground/network changes, and survives app termination. A supported `source` marker reconciles receipts after lost responses. Journal identity is bound to the credential fingerprint; each sync operation is bound to the API session revision. Explicit validation failures remain visible and do not block later captures. The API has no atomic idempotency key: ambiguous attempts with no visible receipt remain “Confirming previous save” instead of being resent. Automatic recovery of that specific state requires server idempotency support. Unlinked catalog ideas and list-item inbox ideas are shown together while preserving their different identities.

**Web:** Budget, Lists, Assignments, and Admin use the existing ephemeral session-sharing WKWebView. Native navigation handles person/gift/event routes, and Settings includes the origin. Document-start injection sets existing web token/expiry keys only in the trusted main-frame origin. Cross-origin links leave the view without credential injection. The bridge still needs a device check against the deployed build before TestFlight.

**Design:** `Tokens/confetti.tokens.json` → `Scripts/generate-tokens.py` → `ConfettiTokens.swift`. Run `--check` in verification. JSON seeds exactly the current web palette/type/spacing/radii/shadows; future web work should generate CSS variables from this same JSON and remove duplicate literals (web untouched here). The `active-theme` response alone selects Christmas; dates never activate it locally. Bundled Montserrat Bold/Open Sans Regular retain OFL licenses. Intentionally light-only until a reviewed dark palette exists. Dynamic Type fonts, adaptive hero layout, native tab/navigation/sheets, semantic labels and ≥44pt controls; native glass stays in system chrome. Together Bow paths mirror `BrandMark.tsx`; icon/launch resources retain that geometry.

| Next milestone / separate feature owner | Existing API surface (under `/api/v1`) |
|---|---|
| People: step-by-step creator, profiles, groups | `GET/POST /persons`, `GET/PATCH /persons/{id}`, `GET/POST /groups`, person occasion/group links |
| Gifts/Ideas: filters, detail, purchase, assignments | `GET/POST /gifts`, `GET/PATCH /gifts/{id}`, `POST /gifts/{id}/mark-purchased`, `/ideas/inbox`, `/lists` and `/lists/{id}/items` |
| Events: native calendar + holiday picker | `GET/POST /occasions`, `GET/PATCH /occasions/{id}`, `/holidays`, `/holidays/active-theme`, `/budgets/occasions/{id}/meter` |
| Share extension: save Safari idea | `POST /gifts`; shared Keychain access group requires signing entitlements + explicit credential scope |
| Countdown widget | App-group cached dashboard + occasion snapshot; no bearer in widget timeline; refresh through app |
| Notifications | Local reminders from occasion dates first; remote pushes need server APNs device registration, delivery and removal endpoints |

People, Gifts, and Events features can run in parallel in separate app feature folders after freezing package DTOs; one integration owner serializes shared `AppModel`/API/navigation edits. Share extension and widgets can follow in separate targets, with one owner integrating project/signing changes. Server session work is independent. Offline fixtures use only the invented Hartwell family. `--fixture sample|empty|christmas|signin` injects transport and blocks fallback web loading; release builds must not expose fixture mode.

## Read-only server smoke check

From `apps/ios/FamilyGiftingKit`, run `swift run fg-smoke --server <url>` with `FG_EMAIL` and `FG_PASSWORD` already exported. Credentials are read only from the environment; use a throwaway account. Output contains endpoint paths and OK, HTTP status, or decoding field path; no tokens, passwords, or response bodies. Empty collections skip dependent detail probes. The tool signs in, then performs only reads. Do not run it against a live server during mocked-only development.
